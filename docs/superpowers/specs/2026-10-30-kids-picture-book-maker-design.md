# 어린이 그림책 만들기 도구 — 설계 문서

작성일: 2026-10-30

## 1. 의도와 이유

아이가 직접 찍은 사진을 배경으로 깔고, 아이가 종이에 그린 그림과 쓴 글씨를 휴대폰으로 찍어 **스캔한 것처럼 배경을 지워** 얹어서, 여러 페이지짜리 그림책을 만든다. 결과물은 **포토북/인쇄 업체에 맡길 인쇄용 PDF**다.

한 권만 만들고 끝내는 게 아니라 앞으로 여러 권을 계속 만들 수 있어야 하고, **다른 부모들도 같은 도구를 쓸 수 있게 나눠 줄 수 있어야** 한다. 사용자는 PC 앞의 부모다(아이는 재료를 만드는 사람이고, 편집은 부모가 한다).

## 2. 목표

- 휴대폰으로 찍은 아이 그림·글씨 사진에서 종이 배경·그림자·누런 기를 지워 투명 배경 이미지로 만든다.
- 사진 배경 위에 그림·글씨·입력 글자를 자유롭게 배치해 페이지를 만든다.
- 여러 페이지 + 앞/뒤 표지로 한 권을 구성한다.
- 업체 전달용 인쇄 PDF(표지/내지 분리)를 내보낸다.
- 작업을 저장해 두었다가 이어서 할 수 있다.
- 설치 없이 링크 하나로 다른 부모도 쓸 수 있다.

## 3. 하지 않을 것 (Non-goals)

- 회원가입, 로그인, 클라우드 저장, 서버 측 처리.
- 업체 주문/결제 연동.
- 책등(spine) 디자인. (업체·페이지 수마다 두께가 달라서 이번 범위에서 제외)
- 모바일(휴대폰) 편집 화면 지원. 휴대폰은 촬영용으로만 쓴다.
- 아이가 혼자 조작하는 아동용 UI.

## 4. 실패로 간주할 것 (Anti-goals)

- 아이 사진이 사용자 컴퓨터 밖(서버, 외부 API)으로 나가는 것.
- 컴퓨터에 익숙하지 않은 부모가 쓰기 어려운 복잡한 화면.
- 인쇄했을 때 흐릿하거나 가장자리에 흰 줄이 생기는 PDF.
- 배경 지우기가 아이 그림의 손맛(크레파스 결, 옅은 칠)을 날려 버리는 것.

## 5. 결정된 사항

### 5.1 형태 (Claude의 판단, 사용자 동의함)
- **정적 웹 앱**: 브라우저에서 모든 처리를 한다. 서버 없음.
- 무료 정적 호스팅(예: GitHub Pages)에 올려 링크로 공유.
- 대상 환경: PC 데스크톱 브라우저(최신 Chrome/Edge/Safari).

### 5.2 재료 (사용자 결정)
- **배경 사진**: 아이가 찍은 사진.
- **그림·손글씨**: 종이에 그린 것을 휴대폰으로 촬영한 사진.
- **입력 글자**: 부모가 키보드로 입력하는 제목·설명 텍스트. 손글씨와 입력 글자 **둘 다** 지원.

### 5.3 배경 지우기 (사용자 결정: "손맛 살리기" 스타일)
- 종이 배경만 투명하게 만들고, 크레파스 결·연필 질감·옅은 칠은 최대한 남긴다. 종이 얼룩이 약간 남는 것은 허용.
- 휴대폰 촬영 특성 보정: 그림자/조명 불균일, 종이의 누런 기.
- 보정 도구 (Claude의 판단, 사용자 동의함):
  - 지우기 강도 슬라이더
  - 지우개 / 되살리기 붓
- 비뚤어진 각도 보정(원근 보정)은 있으면 좋지만 구현 방식은 빌더 재량(5.9 참고).

### 5.4 페이지 구성 (사용자 결정)
페이지마다 두 가지 중 고를 수 있다.
- **A. 사진 가득**: 사진이 페이지 전체(재단 여유분 포함)를 채우고, 그 위에 그림·글씨를 얹는다. 입력 글자에는 가독성용 반투명 띠를 옵션으로 둔다.
- **B. 양쪽 펼침면**: 한 쪽은 사진+그림, 맞은편 쪽은 글씨 중심. 두 쪽이 한 장면.

모든 요소(그림, 손글씨, 입력 글자)는 **마우스로 끌어서 이동·크기 조절**할 수 있다. 처음엔 기본 위치에 놓인다.

### 5.5 표지 (사용자 동의함)
- **앞표지**: 사진 배경 + 그림 + 책 제목 + "글·그림 ○○○"(아이 이름). 편집 방식은 A 구성과 같다.
- **뒤표지**: 사진 또는 그림 한 장 + 짧은 글 정도의 단순한 면.
- 책등 없음.

### 5.6 인쇄 출력 (사용자 동의함)
- 판형 프리셋: **정사각 20×20cm, A5, A4**. A5와 A4는 **세로형/가로형**을 고를 수 있다(사용자 결정). B 펼침면은 판형 두 쪽을 나란히 붙인 크기다(예: A4 가로 → 594×210mm).
- 재단 여유분(bleed) **사방 3mm**.
- 해상도 **300dpi** 기준.
- 사진/그림의 실제 해상도가 인쇄 크기에 비해 부족하면 **화질 경고** 표시.
- **표지.pdf**와 **내지.pdf** 두 파일로 분리해 내보낸다.
- (Claude의 판단) 특정 업체를 정하지 않았으므로, 국내 포토북 업체에서 가장 무난한 형식에 맞춘다.
  - **색 공간:** sRGB 기준이며 CMYK 변환은 하지 않는다.
  - **페이지 처리:** 각 페이지를 300dpi 이미지 한 장으로 평탄화해서 PDF에 넣는다. 투명도 처리 문제를 피하기 위해서이며, 입력 글자도 이미지로 같이 굳는다.
  - **압축:** 고품질 JPEG를 쓴다. 파일 용량 제한은 고려하지 않는다.
- (Claude의 판단) 표지.pdf는 앞표지와 뒤표지를 각각 한 쪽씩 담은 2쪽짜리 PDF다. 각 쪽은 판형 크기에 재단 여유분 3mm를 더한다. 하드커버 감싸기 여백이나 펼친 한 장짜리 표지는 지원하지 않는다.

### 5.6.1 내지 쪽 배치 규칙 (Claude의 판단)
- 내지 1쪽은 오른쪽 면에서 시작한다.
- B 펼침면은 항상 왼쪽 면에서 시작해야 한다. 순서가 어긋나면 편집 화면에서 알려 주고, 빈 쪽을 끼워 넣어 맞출 수 있게 한다.
- 내보낼 때 전체 쪽수가 짝수가 아니면 마지막에 빈 쪽을 하나 더한다.
- 최소 쪽수나 4의 배수 같은 업체별 규칙은 강제하지 않는다.

### 5.7 저장 (사용자 결정 + Claude의 판단)
- 작업은 브라우저에 **자동 저장**되고, 다시 열면 이어서 작업할 수 있다.
- 여러 권을 만들 수 있으므로 책 목록에서 골라 여는 구조.
- 백업·다른 PC 이동용 **책 파일 내보내기/불러오기**(이미지 포함 단일 파일).

## 6. 빌더 재량으로 남긴 것

- 프레임워크, 라이브러리 선택(캔버스 편집, PDF 생성, 이미지 처리).
- 배경 제거 알고리즘의 구체적 방식(조명 평탄화 + 임계값, 색 거리 등). 단, 브라우저 안에서 동작해야 함.
- 원근 보정을 자동/수동(네 모서리 지정) 중 어떻게 할지, 또는 1차 범위에서 뺄지.
- 펼침면(B)을 PDF에서 두 쪽으로 쪼개 내보내는 방식.
- 입력 글자 폰트 선택(아이 책에 어울리는 한글 폰트, 라이선스상 재배포 가능한 것).
- 화면 디자인 세부, 실행 취소(undo) 지원 범위.
